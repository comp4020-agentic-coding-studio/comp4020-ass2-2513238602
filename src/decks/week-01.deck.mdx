# Mastery is a loop

One champion. One decision. One better next test.

```notes
Open with the course promise: students are not here to memorise a fixed build. They are here to maintain a trustworthy way of improving.
```

---

## More games ≠ better practice

**Volume** repeats whatever you already do.

**Practice** chooses a behaviour, adds a condition, and checks the evidence.

```notes
Ask students for one habit they have repeated for fifty games without ever isolating it.
```

---

{/* _class: banner */}

## Start smaller than the result

Not “win lane.”

**Reach wave three with the planned health, position, and cooldown state.**

```notes
The observable unit must be small enough to reproduce. Rank and win rate matter over time, but they cannot diagnose one decision.
```

---

## Five actions close the loop

1. **Plan** — name the condition and prediction
2. **Drill** — remove noise and repeat the action
3. **Test** — add an opponent, then a real match
4. **Review** — freeze before the outcome
5. **Revise** — change one variable and schedule the re-test

```notes
Move through the list once, then point out that step five creates the next step one. A review without a scheduled test is unfinished.
```

---

## Three loops run at once

### Mechanics
Can I execute the action?

### Matchup
Does it work against this response?

### Global
Does it create the right map decision?

```notes
The course uses the same five actions at three scales. Improvement in one loop does not substitute for the others.
```

## “Counter” is the start of a question

> Which interaction, under which conditions, denies which plan—and what response will we test?

```notes
Do not let students settle for champion-name versus champion-name claims. Require level, wave, items, cooldowns, side, and jungle pressure when they matter.
```

## Evidence changes the rule

| Before | Test | After |
|---|---|---|
| “I should always extend for W2.” | Three resets + one match timestamp | “Extend only when the exit remains open.” |

The failed hypothesis belongs in the playbook.

```notes
Reward useful failure. A portfolio that hides rejected ideas cannot demonstrate a real review loop.
```
